Linux terminal (experimental) → BusyBox on the same engine.

Our own engine for Windows programs: a 64-bit .exe runs here without Wine or Linux, with a fixed amount of real RAM and the rest of its memory in swap on this device's storage (OPFS). Stage 1: no windows yet, console programs only.

Run a Windows program

The stage 1 test is a normal 64-bit program with a DLL: integers, floating point (SSE2), sorting through function pointers, heap, TLS, TEB/PEB and memory checks, each compared with the expected result. The stage 2 test uses the real msvcrt.dll API: printf and the string functions run Wine's own msvcrt code compiled to wasm, reading the program's memory through the engine's page table. "Run 7-Zip benchmark" runs 7-Zip 23.01 (7za.exe, one file, LGPL; license in bin/7za-license.txt) with b -md18 -mmt and the chosen cores, or with the arguments in the box. "Open .exe" runs your own console program: select the .exe, its DLLs and any data files together, type its arguments in the box (for 7-Zip: i, b -md18, x file.zip -y, a out.7z file.txt); files it creates can be downloaded at the end; it stops at the first Windows function that does not exist here yet and names it.






Measurements



  
1. Engine proof

  
test.exe (x86-64) runs a CPU loop, reserves more memory than the real RAM and checks every page, then calls a "Wine side" function compiled to wasm that reads its memory through the page table.

  

    
    
    
    
  

  

  






  
2. Swap cost (OPFS)

  
Time to read or write one 4 KB page at a random place in a 64 MB file, from a worker.

  
  






  
3. Draw calls per frame

  
How long the GPU path takes for N separate draws in one frame (WebGPU if available, else WebGL2).

  
  






  
4. Memory limits (the tab may reload)

  
Calibration grows wasm memory in 128 MB steps. Textures uploads GPU textures in 128 MB steps. Each step is saved first, so if the tab reloads the last saved step is the limit. Compare both: if textures go well past the wasm limit, GPU memory does not count against the tab.

  

  






  
5. Combined budget (the tab may reload)

  
Uses the calibration above: about 70% of the tab limit, split into fixed real RAM for the engine and a fixed GPU texture pool. Then it streams far more textures than the pool holds for 30 s: the least used ones leave the GPU and come back from OPFS when needed.
