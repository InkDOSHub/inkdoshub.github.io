# 021 · Integrity: SHA-256 checks and protection against altered HTML/JS (2026-11-01)

## How each version authenticates files

| Version | Where files come from | Check |
|---|---|---|
| Web (Safari, Chrome…) | GitHub Pages over HTTPS | TLS (the browser checks the certificate of `inkdoshub.github.io`). |
| Offline copy (Home Screen, Safari) | Downloaded once, then served by `sw-portal.js` | **New:** every file is hashed with SHA-256 (`crypto.subtle`) and compared with the 4th field of `inicio/manifesto.json` before it is stored. A mismatch stops the download and nothing is stored ("Failed, try again"). |
| Windows app (Electron) | Disk copy or site | Every file checked against the same SHA-256 before it is served (log 018). Installer and Webcam app checked against the SHA-256 published in their releases. |
| XeOS | Always from the site (no service worker) | TLS only. |

`inicio/manifesto.json` is regenerated by `tools/portal_manifesto.py` on every push (`manifesto-offline.yml`), so its hashes always describe the
files in `main`.

**What this protects against:** stale or broken CDN copies (the 2026-10-29 problem), truncated downloads and files changed in transit or
on disk (Windows). **What it does not:** someone with write access to this repository, who could change a file and its hash together. That
is covered by GitHub account security (2FA) and the public git history.

## Content Security Policy on every Hub page
Before, only the InkDOS apps and the Whiteboard had a CSP. Now these pages have one too: home screen, Photos, Video (and editor), Music,
Recorder, Transfer, Webcam, Edit PDF, Code, WordCraft, GridCraft, DeckCraft, Linux terminal and the Windows downloads page.

Common rules: scripts only from this site (`script-src 'self'`, inline scripts only by SHA-256 hash), no plugins (`object-src 'none'`),
no `<base>` tricks (`base-uri 'none'`), no form posts (`form-action 'none'`), frames only from this site, network only to this site except:

| Page | Extra network allowed | Why |
|---|---|---|
| Transfer, Webcam | `0.peerjs.com` (https, wss) | Pairing server |
| Linux terminal | `wisp.mercurywork.shop`, `relay.widgetry.org` (wss), `cloudflare-dns.com` | Linux internet and DNS |
| Windows downloads | `api.github.com` | Release sizes and dates |
| Home screen | images from any https site | Icons of the person's own webapps |

`'wasm-unsafe-eval'` is allowed only where WebAssembly runs (terminal, video editor, recorder). Even if an attacker managed to inject
HTML (for example through a file name), an injected `<script>` or `onclick` would not run, and data could not be sent to another server.

The three inline `onclick` handlers (empty-screen "Open" buttons in Photos, Video and Music) became `data-abrir`, handled in `assets/midia.js`.

**Test:** Playwright over the 16 pages: no CSP violations and no JS errors; the "Open photos" button still opens the file picker. Offline
copy: a tampered `apps/quadro/index.html` was refused and not stored; the untampered one was stored.

## Not done
- Subresource Integrity (`integrity=` on `<script>`): all scripts are same-origin, so it adds nothing over TLS + CSP and would need updating
  on every change.
- Code signing of the Windows `.exe` (SignPath declined on 2026-10-29).
